## 저는 이런 사람입니다

> **데이터 파이프라인과 AI 플랫폼을 만드는 데이터 플랫폼 엔지니어**

데이터를 수집하는 배치에서 시작해 그 배치가 돌아가는 플랫폼으로, 그리고 그 데이터를 누구나 꺼내 쓸 수 있게 하는 AI 플랫폼까지 일의 범위를 넓혀 왔습니다.
DE 중에서도 스키마와 마트를 설계하는 쪽보다 **파이프라인이 실제로 돌아가게 만드는 쪽**에 강점이 있습니다.
Airflow 오케스트레이션부터 Kubernetes 워크로드, 스토리지와 컨테이너 런타임까지 문제가 생긴 계층을 끝까지 따라 내려가 직접 고칩니다.

| 흐름 | 해 온 일 |
|---|---|
| **Data Foundation** | API·크롤링 기반 데이터 수집 파이프라인 설계와 운영, ETL 단계에 데이터 품질 검증 내장, 레거시 파이프라인 모듈화 |
| **Data Platform** | 베어메탈 배치 서버를 Kubernetes 클러스터로 통합, Airflow on Kubernetes 실행 구조 설계, 사설 레지스트리 기반 CI/CD, 클라우드 DW 전환 |
| **AI Agent Platform** | MCP 서버 개발과 컨테이너 배포 표준화, LLM 멀티에이전트 라우팅 설계, 트레이싱 기반 답변 품질 모니터링 |
| **Enterprise AI Enablement** | AI 코딩 에이전트가 쓰는 데이터 API와 가이드 설계, 지식그래프 기반 GraphRAG 데이터 질의, 인증 게이트웨이를 둔 MCP 연동 |

**주로 쓰는 기술** — Airflow · Kubernetes(RKE2) · Helm · Snowflake · Python · SQL · AWS · Neo4j · MCP · Claude Code

## 왜 블로그를 시작하나

일을 하다 보면 경험은 쌓이는데 정리되지 않은 채 흩어집니다.
작업 일지와 메모에는 남아 있지만, 그것만으로는 한눈에 보이지도 않고 누군가에게 건네기도 어렵습니다.
그래서 세 가지 이유로 정리를 시작합니다.

- **한 판으로 보기 위해** — 흩어진 경험을 프로젝트 단위로 묶어서 전체 흐름을 한눈에 볼 수 있게 합니다.
- **더 자세히 남기기 위해** — 이력서 한 줄에는 담기지 않는 설계 판단, 시행착오, 트러블슈팅을 남깁니다.
- **공유하기 위해** — 필요할 때 링크 하나로 건넬 수 있는 형태로 만듭니다.

## 어떤 블로그가 될까

이 블로그는 개념을 A부터 Z까지 차근차근 공부하는 노트가 아닙니다.
**해낸 것과 고민한 것을 정리한 기록집**입니다.

- 어떤 문제가 있었고, 어떤 선택지 중에서 무엇을 왜 골랐는지
- 그 과정에서 어디서 막혔고, 어떻게 풀었는지
- 결과가 어땠고, 다시 한다면 무엇을 바꿀지

이렇게 정리해 두고 결과물을 보여줘야 할 때 꺼내 쓰려고 합니다.
그리고 저와 같은 고민을 하고 있는 누군가에게 참고 자료가 되었으면 합니다.
